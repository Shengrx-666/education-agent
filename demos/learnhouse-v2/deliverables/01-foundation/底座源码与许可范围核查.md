## 3. 必须改造的权限差距

V2 规格 P03/P05/P07–P13/P15/P20 与 AC02 要求管理员主要管理运行和授权元数据，默认不能读教学正文、提交、答案，也不能改分。上游有组织隔离和本人数据保护，但管理员/维护者的权限语义不同：

1. `apps/api/src/services/setup/setup.py:28` 的默认 Admin（ID 1）把 courses、activities、assignments 等 CRUD 全置真；ID 2 为 Maintainer，ID 3 为 Instructor。`apps/api/src/security/rbac/constants.py` 明确 admin/maintainer 特权集合。只把 `role.rights` 改小还不够，因为还存在基于角色 ID 的旁路。
2. `apps/api/src/security/rbac/resource_access.py:343` 的 dashboard 读取优先放行 admin/maintainer；同文件约 `416` 行的 public-view 路径亦直接放行。`rbac/rbac.py:479` 根据目标组织判断 admin/maintainer；这已避免跨组织混用，但仍不是 V2 的课程、班级、动作粒度。
3. `resource_access.py:191` 及 `rbac/rbac.py:528` 存在 backoffice 全资源旁路。`User.is_backoffice_staff` 映射的是数据库列 `user.is_superadmin`（`db/users.py:275` 起），不能忽略该列因 Python 属性改名而误判不存在。不要给 V2 演示管理员这一标记。
4. `services/courses/activities/assignments.py:139` 的 `authorize_assignment_access` 对会话调用课程级 checker；`:184` 的 `_is_assignment_instructor` 用课程 update 判定教师；`:3410` 列出提交时教师不再受本人过滤；`:4227` 的评分入口也以课程 UPDATE 为准。V2 需要明确 `submission.read` 与 `grade.confirm/revise`，并同时约束课程、班级、任务、学生，而非所有课程编辑者均可批阅。
5. API token 在 assignments 权限桶通过后具有 instructor 可见性（同服务 `:184`）；不能把可编辑课程或拥有普通组织 token 当成受限自动发布/评分服务身份。V2 服务身份须绑定动作、对象范围、策略版本，完成回调时再验权。
6. 私人笔记是可保留的例外：`services/courses/activities/learner_notes.py:1` 明确每次查询限本人，无管理员跨用户列表；`:195` 起 `_own_note` 联合 note_uuid 和 user_id。不要为实现 A06 或 T11 打开跨用户原文读取；另建学生显式共享的授权对象。
7. 通用 group membership 主要解决访问资源，`usergroup_manager` 的 progress 权限不能自动推导正式提交正文批阅权。P04 要求 Demo 入班/退班由 A03 管理，教学分组不扩展平台授权。

最小安全做法是为 V2 建独立的动作授权判定函数，入口先检查真实身份、对象归属、班级/个人范围、动作、状态、授权有效期，再读正文或执行写入。V2 管理员不使用上游 ID 1/2 和 backoffice 标记；只授予必要管理元数据权限。若复用同一上游 UI/原 API，必须同步约束课程读取、附件、检索、引用、任务/提交、评分和 token 旁路；只保护新增路由或只隐藏菜单不能通过 AC02。若用全局 `public=true` 发布演示课程，管理员与匿名者也可按 public 分支读取，因此 V2 受控课程须采用非公开+明确授权范围。

管理员给自己新增教学正文范围须由独立授权主体批准（P02/A03）；不得使用已有角色编辑接口替自己赋予 Admin/Instructor 或作者身份来绕过此要求。Demo 可预置固定范围，仍须在服务端拒绝自我提权请求。

## 4. 版本、提交和审计不能直接复用的原因

**活动版本是编辑撤销历史，不是永久证据。** `services/courses/activities/versioning.py:21` 定义 `MAX_ACTIVITY_VERSIONS = 20`，`:64` 的清理函数删去更早记录。`ActivityVersion` 只快照 content，任务题目和量规另存其他表。V2 应保存被发布及被任务引用的不可变资源快照；已提交引用不得被活动版本清理或课程物理删除级联消失。

**重试会覆写当前记录。** `services/courses/activities/assignments.py:3767` 的 retry 会保留汇总行、递增次数、重置状态/成绩、删除题目作答，并删除本次 AI grade。`user_audit_event` 的学习者事件可保留过往部分事件元数据，但不等于保存完整作答/题目/量规快照。V2 AC06/AC09 应另存 attempt、正式 submission、评分修订；订正创建新尝试，复核保存原结果与修订理由，不能把该 retry 路径原样开放给 V2。

**编辑题目可能主动重评旧结果。** 同服务 `update_assignment_task` 约 `2007` 行检测题型、contents、max_grade_value 变化后调用 `_regrade_graded_submissions`。V2 T09 明确“已收提交后不得静默覆盖原规则”，所以修改必须产生新资源/量规版本；对旧提交重评另有显式动作与审计。不要直接使用上游更新接口改动已布置 V2 任务。

**已有成绩计算不等于版本化成绩。** 服务有手动/客观题/AI 建议的分离逻辑和待交状态防护，可作为计算与 UI 的参考；但现有 grade/feedback 是当前状态。V2 要将 AI 建议、客观规则生效结果、教师确认/修订结果分开存证，再通过幂等事件更新画像和推荐。运行异常不应写成学生答错，待批结果不应进入正式掌握更新。

**企业审计 hook 在 OSS 下为空。** `core/ee_hooks.py` 的 `audit_event` 无 `record_audit_event` hook 时直接返回，不能把调用它等同于写入审计。社区 `db/user_audit_events.py:23` 明确只记录学习者动作，不覆盖 authoring/admin/AI editor generation 等操作。V2 A06 需要社区自建业务审计事件，记录 actor/action/target/scope/policy-version/result/reference 等元数据；正文、密码、令牌、模型全文不得混入默认 A06/A05 返回。

## 6. 后续验收重点与证据边界

AC02 必须用替换 course/submission/file 编号测试学生、教师、管理员三类真实账号；另测原上游路由和下载路径，不能只测新增页面。AC06/AC09 要在旧提交后改题、重试、改分，确认旧正文/量规/分数仍可追溯；AC04/AC05 要分别验证审核失败拒发、规则模板通过且无人工门禁才可自动发布；AC10/AC11 要验证撤权后的旧会话、取消后的迟到回调、重复回调不会越权或重复生效。AC14 保留私人笔记本人隔离并单测共享撤回。

本次静态审计不声称任何用例已运行通过，不声称企业模块已经可用，不声称研究生成/画像算法已经接通；T12 教学质量评估仍按 V2 标记规划。已确认能直接减少重建量的是上游真实身份、课程/活动结构、基础作业界面与私人笔记；已确认会阻断 V2 验收的是管理员教学超权、课程编辑与批阅耦合、历史证据被重试/清理覆盖，以及 OSS 缺少完整业务审计。

## 7. 本轮实际启动新增证据（由主代理执行）

2026-11-20，主代理在私有 PostgreSQL 14.24 环境尝试真实 LearnHouse 空库启动，首次在缺少 pgvector 时因 `vector` 类型不存在而失败。此观察收窄了“向量检索依赖可选”的说法：对于该固定提交完整 SQLModel metadata 的空库初始化，`course_embedding.embedding` 使用 Vector 类型，不能把 pgvector 视为可直接省略的启动依赖。
