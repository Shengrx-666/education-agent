# V2 本地 Demo 验收交付物

本目录记录本地隔离数据库 `learnhouse_v2_demo` 上的真实 HTTP 验收。所有用户、材料、答案、成绩均为明确标记的合成演示数据，不是研究实验结果。验收不请求外部模型、不运行学生 Java 代码，也不通过测试夹具跳过权限检查。

## 运行方式

先按项目运行说明启动已加载 `EA_DEMO_MODE=1` 的本地 API。以下命令从交付包根目录执行：

```bash
.runtime/api-venv/bin/python scripts/seed_v2_demo.py
.runtime/api-venv/bin/python scripts/test_v2_demo.py
.runtime/api-venv/bin/python scripts/test_v2_demo.py --section supplemental --output deliverables/05-demo-acceptance/http-supplemental-results.json
.runtime/api-venv/bin/python scripts/test_v2_demo.py --section final-gates --output deliverables/05-demo-acceptance/http-parent-policy-results.json
```

种子脚本仅允许连接专用的 `learnhouse_v2_demo`，重复执行保持同一批种子对象及账号。HTTP 验收每次新建名称含“验收演示”的作业、提交和笔记，保留不可变历史，不清空既有课堂演示数据。

若连接本轮联调中较早建立的策略，验收脚本会通过管理员 API 在原家族追加标准字段的新版本，课程策略引用最新全局策略；原作业仍冻结旧版本。专项模式会短时对教师 B 授予/撤回 A 班权限、停用/恢复学生 B、撤销其旧会话，并追加 B 课程的限制/恢复策略版本；安全恢复写在 `finally` 中。运行专项期间不要用学生 B、教师 B 做人工演示。

`final-gates` 是最终补丁的定向验收：追加规则相同的全局新版本，确认旧父版本不能继续创建内容/课程策略，再为两门课追加与新全局版本对齐的策略；并检查管理后台任务列表与任务详情的并发版本标识一致。此模式会更新当前策略版本号，保留原作业冻结引用。

- API：`http://127.0.0.1:8138`。
- 所有写操作的来源：`http://localhost:3300`；缺失或外来 Origin 被拒绝。
- 私有凭据：`.runtime/demo-accounts.local.json`，随机生成密码，文件权限必须为 `0600`，不得提交 Git 或放入交付包。
- 验收输出：`http-results.json`，仅包含操作名称、HTTP 状态、错误码与演示对象 ID；不含密码、Cookie、笔记或答卷正文。
- 可用 `--output` 指定另一份报告，`--base-url` 仅允许本机 HTTP 地址。

## 种子账户与边界

| 账户键 | 演示身份 | 课程与班级 | 权限边界 |
|---|---|---|---|
| `student_a` | 学生林同学 | Java 条件与分支 / A 班 | 仅本人当前班级、本人草稿、答卷、成绩及私人笔记 |
| `student_b` | 学生陈同学 | Java 循环基础 / B 班 | 与 A 班学生隔离 |
| `teacher_a` | 教师周老师 | Java 条件与分支 / A 班 | 授权范围内备课、布置、评阅、复核、学情；默认不能读私人笔记/草稿 |
| `teacher_b` | 教师吴老师 | Java 循环基础 / B 班 | 与 A 班教师隔离 |
| `admin` | 平台管理员 | 平台元数据 | 授权、策略、运维和审计元数据；无学生正文权限 |

全部账户使用关闭上游 CRUD 权限的自定义角色，不授予 LearnHouse Admin、Maintainer 或超级管理员。业务权限从 `ea.principal`、实际 `ea.action_grant` 和当前班级成员关系计算。初始授权的签发与批准 actor 分离，并明确为合成初始化配置，不冒充真实审批。

每门课提供可阅读的资料、知识点、策略、量规和一份已布置的混合练习。种子不预造提交、成绩、学情证据，用户可以从未提交状态演示完整过程。

## 验收覆盖

| 维度 | 验证内容 |
|---|---|
| 实际登录 | 五个真实账号通过上游 Cookie 登录；会话角色由服务器计算；未登录拒绝 |
| 请求边界 | 缺失/外来 Origin 拒绝；旧课程/活动接口关闭；伪造角色请求头不提权 |
| 对象隔离 | 学生之间、跨班教师、平台管理员均不能读取越权课程/资料/答卷 |
| 幂等与版本 | 草稿保存与提交重放；同键异内容拒绝；缺失和陈旧版本拒绝；提交后不能覆盖原始答案 |
| 成绩历史 | 混合题等待教师；真实教师评价显式生效；并发改分只有一个版本胜出；旧成绩和原答卷保留 |
| 复核与学情 | 学生提出复核，教师给出结论；改分触发新统计版本，并明确不是知识掌握概率 |
| 规则演示 | 固定判断题模板、服务端校验、发布、布置、作答、确定性判分闭环 |
| 能力如实显示 | 研究生成/AI 评分未接线时拒绝执行；规则资料与成绩标记演示来源 |
| 笔记隐私 | 私人笔记默认不可见；学生显式授权教师；教师阅读与画像用途独立；撤回立即生效 |
| 专项管理写入 | 自授权拒绝、临时授权及撤回、撤权后旧 Cookie/幂等命令不能绕过、账号停用与会话撤销、测试结束恢复 |
| 专项内容与策略 | 跨课程来源/错误哈希/错误答案类型拒绝；策略版本并发控制；课程不能放宽父策略；新命令不能引用旧策略绕过限制 |

## 范围限制

通过本验收意味着当前本地演示链路与列出的权限边界可复现，不意味着完成生产上线审计、全量浏览器兼容、负载/故障恢复测试或研究效果验证。多智能体、认知双身、动态认知画像、推荐模型及教学质量研究指标仍需单独接入与实验评估。浏览器页面与截图验证由项目总体验收单独记录。
