# 本地 Demo 文件监听故障修复

日期：2026-11-20。

## 故障原因

页面显示 `Can't resolve '@emoji-mart/data'`，详细错误是 `OS file watch limit reached`。实际检查两个 emoji 包均已安装且可以加载；Next 自身模块也出现同类错误。同一 Linux 用户的 inotify 监听数达到 65,536 上限，其中 VS Code 文件监听器占 63,929，原 Next 进程占 1,547。没有重复启动的 Demo 实例。

## 本次变更

- `scripts/foundation_web.py` 显式使用 `next dev --webpack` 并设置 `WATCHPACK_POLLING=1000`，以一秒轮询检查文件变化。仅设置轮询变量不会改变 Turbopack 的监听方式，因此两个配置须配套使用。相关 CLI 选项已核对安装版本的文档及 [Next.js 官方文档](https://nextjs.org/docs/app/api-reference/cli/next)。
- 启动器设置专用 `EA_DEMO_MODE=1`。在该模式中，站点根路径 `/` 跳转到 `/education/login`；其他部署没有开启此模式时保留上游行为。
- `scripts/local_demo.py` 在已登记进程仍存活、但健康检查失败时提示先停止再启动，避免重复启动覆盖进程登记。
- `RUN_LOCAL.md` 补充 VS Code 3300 端口转发、轮询启动及故障恢复步骤。

通过原启动器安全重启，数据库与教学数据保留。没有修改系统监听上限或终止 VS Code。轮询模式首次编译可能更慢，并会增加周期性文件检查。

## 验证结果

- 新 Next 进程的 inotify 实例和监听数均为 0；检查时同用户总监听数降为 63,975/65,536。此为当时运行快照，不保证其他进程的后续占用量。
- API 与 Web 健康检查通过；再次运行 `start` 复用现有健康实例。
- 真实浏览器验证根路径跳转、教师/学生/管理员登录及对应首页，三个角色的页面脚本错误均为 0。详见 `watch-fix-browser-results.json`。测试未修改教学业务数据。
- TypeScript `tsc --noEmit --incremental`、修改的 Python 脚本语法检查及 `git diff --check` 通过。
- 本次验证范围为启动故障修复与上述页面，未重新执行全部教学业务回归或生产部署验收。

## 使用方式

当前工作区服务已启动，浏览器打开 `http://localhost:3300/education/login` 并按 `Ctrl+Shift+R` 刷新即可。使用远程 VS Code 时保持远程 3300 到本机 3300 的端口转发。

日后重启仍使用包根目录下的以下命令：

```bash
python scripts/local_demo.py stop
python scripts/local_demo.py start
```

本说明对应更新后的本地源码交付包；此前下载到其他机器的旧包不会自动更新。
